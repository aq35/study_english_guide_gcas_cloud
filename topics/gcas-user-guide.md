## 1. GCAS とは

- ガイド: GCAS(Government Cloud Assistant Service: ガバメントクラウド支援サービス)は、デジタル庁のガバメントクラウドが提供する**Webサービス**。府省庁・地方自治体・独立行政法人・事業者が、クラウド環境の**利用手続き・環境管理・技術支援をワンストップ**で行える。

| 機能 | ガイドの説明 |
|---|---|
| 認証・アクセス管理 | **1つのGCASアカウント**で、GCASの各機能と複数のクラウド環境(CSP環境)に安全にログインする。許可された人だけが、適切な権限でアクセスできる |
| クラウド環境の申請・管理 | 利用申請に基づき、組織専用のCSP環境を**払い出す**。ユーザー(GCASアカウント)の管理と確認、環境へのアクセス管理 |
| 導入・運用サポート | GCASガイド、GCASヘルプデスク、地方公共団体向けコストダッシュボード |

- ガイド: はじめるには、「利用が決まったら、**まずGCASアカウントの取得から**」。

推論: 今までの教材の「原則」(ネイティブ利用、責任共有など)の入口が、このGCASアカウントだと読める。アカウントがないと、CSP環境にも、メンバー専用ページにも入れない。

## 2. GCASアカウントの取得: 4ステップ

| ステップ | やること | ガイドの要点 |
|---|---|---|
| STEP1 準備 | 自分のロールと承認者を確認し、申請に必要な情報・マイナンバーカード・MFAデバイスを用意する | 個人では申請できない |
| STEP2 利用申請 | マイナアプリでマイナンバーカードによる本人確認 → Webフォームで申請 | ロールによっては、電子署名(GPKI/LGPKI)による職責確認が要る |
| STEP3 初期設定 | アカウント発行後、初期パスワードの変更と2段階認証の設定 | **2週間以内**に2段階認証を設定しないと、アカウントがロックされる |
| STEP4 次のステップ | GCASポータルにアクセスして、各種サービスを使う | 90日以上使わないアカウントは、無効化される可能性がある |

### 2.1 誰が申請できるか

- ガイド: ガバメントクラウドの利用が承認された**利用機関**(府省庁、地方公共団体等、独立行政法人等、公共SaaS事業者)の担当者と、そこから業務委託を受けた**開発運用委託業者**の担当者。**個人での申請はできない**。開発運用委託業者は、利用機関との**守秘義務契約を締結してから**申請できる。
- ガイド: 申請に使うWebフォームのURLは**一般公開されていない**。所属組織の管理者から入手する。職場メールアドレスは、常用のものを使う(メーリングリストは不可)。

### 2.2 組織の構造とロール

- ガイド: アカウントは、2つの組織区分(**利用機関**と**開発運用委託業者**)に分かれる。それぞれに、横断管理の**PMO**(利用機関単位または事業者の法人単位で1つ)と、その配下の個別システムの**PJMO**(1つ以上)がある。
- ガイド: PMO/PJMOは国の行政機関の用語。GCASでは便宜上、府省庁以外にも使う。

| ロール | 概要(ガイド) | MFA |
|---|---|---|
| 責任者 | グループの特権管理者。アカウント登録申請の承認、メンバー管理など | ハードウェアMFA必須 |
| 担当者(管理者) | 管理者。申請の承認はできるが、メンバー管理以外の管理操作。**申請時は選べない**(「担当者」で作ってから、責任者がロール変更で付与) | ハードウェアMFA必須 |
| 担当者 | GCASガイド・ヘルプデスクなどを使う | ソフトウェアMFA(下の例外あり) |

- ガイド: 1つのアカウントに複数のロールを付与でき、切り替えて運用する。ただし、**利用機関と開発運用委託業者をまたぐ付与や切り替えはできない**。
- ガイド: 承認の流れの例。プロジェクトチームの担当者は、プロジェクトチームGCAS責任者が承認する。プロジェクトチームの責任者は、利用機関GCAS責任者が承認する。

### 2.3 準備物

| 準備物 | ガイドの説明 |
|---|---|
| マイナンバーカード | 本人確認に使う。利用者証明用電子証明書の暗証番号(数字4桁)と、券面事項入力補助用の暗証番号が要る |
| スマートフォン(マイナアプリ) | カードの読み取りに使う。使えなければ、PCで読み取る電子署名方式(デジタル庁GPKI電子署名アプリ、ICカード読取装置、JPKIクライアントソフト。**Windows必須**) |
| MFAデバイス | 初期設定の2段階認証に使う(次の節) |
| 利用機関GCAS責任者のみ | 任命通知書への電子署名(府省庁=官職証明書、地方公共団体等=職責証明書)。公共SaaS事業者は、電子署名ではなく委任状を押印してメールで送る |

### 2.4 2段階認証(MFA)

- ガイド: GCASアカウントはクラウド環境への**管理アクセス**を伴うので、パスワードに加えて2段階認証が**必須**。

| 種別 | 意味(ガイド) | 対象 |
|---|---|---|
| ハードウェアMFA | FIDO/FIDO2準拠の**セキュリティキー**(物理デバイス) | 責任者、担当者(管理者)、および**CSPの本番相当環境**にアクセスする担当者 |
| ソフトウェアMFA | セキュリティキー、認証システムアプリ、Googleからのメッセージのいずれか | 上記以外 |

- ガイド: 「本番相当環境」は、**本番環境・共通運用管理環境・CI/CD環境**。CI/CD環境も入る点に注意(推論: 本番に変更を入れられる経路だから、と読める)。
- ガイド: 初期設定の手順は、初期パスワードを変更し、Googleアカウントのセキュリティ設定で2段階認証を有効にする。ソフトウェアMFAの人は、パスワードを失くしたときに備えて**複数の認証方式**(バックアップコードも可)を設定することを推奨する。
- ガイド: ロックの解除は、所属グループの責任者(または担当者(管理者))ができる(地方公共団体等の担当者(管理者)は不可)。**解除の有効期間は1時間のみ、1人につき3回まで**。セキュリティキーは第三者に悪用されないよう、適切に管理する。

### 2.5 アカウントの削除

- ガイド: 異動や離任で不要になったら、**速やかに削除**する。GCASポータルの「GCASシステム情報登録」から、セルフ削除できる(推奨)。ただし、組織で**唯一の**利用機関GCAS責任者や、プロジェクトチームで唯一の所属アカウントは、セルフ削除できない。その場合は、責任者が「削除申請書」をヘルプデスクへ送る。開発運用委託業者のアカウントも、利用機関またはプロジェクトチームの責任者が申請する。

## 3. GCASポータルでできること

| サービス | 内容(ガイド) |
|---|---|
| GCASシステム情報登録 | ガバメントクラウド利用に係る各種手続き。**責任者と担当者(管理者)のみ**。担当者は使えない |
| GCASガイド | 利用検討に必要な情報(この教材が読んでいる公開ページ) |
| GCASガイド(メンバー専用ページ) | 利用に必要な手続き・作業の詳細。**GCASアカウントが必要** |
| GCASヘルプデスク | 問い合わせと、その後のやり取りの一元管理 |
| 地方公共団体向けコストダッシュボード | クラウド利用料金情報(地方公共団体向け) |

推論: 公開ページは「何を選ぶか」、メンバー専用ページは「どう手続き・作業するか」と、役割が分かれている。この教材は、公開ページの範囲までしか読めていない。

## 4. CSP環境へのアクセス制御(CEP)

- ガイド: CSP環境への端末アクセスを制御するため、Chrome Enterprise Premium(**CEP**)で、**接続元端末**または**接続元IPアドレス**によってアクセスを制限できる。CEPのライセンスは、ガバメントクラウドチームが用意して付与する(利用者が買う必要はない)。

| 制限方法 | 仕組み(ガイド) | 前提 |
|---|---|---|
| 接続元端末制限 | CEP + Endpoint Verification拡張プラグインで、登録済みの端末シリアル番号に基づく | Chromeブラウザ。**GSS端末は拡張プラグインを入れられず、使えない** |
| 接続元IPアドレス制限 | 管理者がPJMO単位で登録したグローバルIPアドレスの範囲に基づく | 特になし |

| 対象 | 方針(ガイド) |
|---|---|
| 府省庁・独立行政法人等・公共SaaS事業者 | 各利用機関の運用方針に任せる(オプション) |
| 地方公共団体 | 総務省のガイドラインを踏まえ、**本番相当環境では必須**(マイナンバー利用事務系で本番環境にアクセスする場合は必須) |

- ガイド: 「接続元端末制限」は、GCASアカウントでの各CSP環境へのシングルサインオンに**一律で適用**される。**本番相当環境だけでなく、検証・開発環境を含む全CSP環境**へのアクセスに効く。

## 5. 困ったとき: ヘルプデスクと緊急アクセス

### 5.1 ヘルプデスク

- ガイド: サポートは2つに分かれる。**ガバメントクラウドの問い合わせはデジタル庁のヘルプデスク**、**CSPに係る問い合わせはCSPサポートを直接**使う。

| 項目 | ガイドの説明 |
|---|---|
| 機能 | オンボーディング(利用開始に必要な設定・手続きの理解)、問い合わせ、Wiki、FAQ |
| ツール | Zendeskで構築。ブラウザからインターネット経由。ログインアカウントは申請に基づいて発行 |
| 稼働 | ツールは24時間365日(メンテナンス時を除く) |
| 回答 | **開庁日9時〜17時**。受付後、**翌開庁日の同時刻以内を目安に1次回答**(最終回答は内容による) |

### 5.2 管理GUIのSSOが使えないとき: GCAS BreakGlass

- ガイド: 通常、CSPの管理GUIはGCASの**SSO**でアクセスする。システム障害でSSOが使えなくなったときのために、**GCAS緊急ユーザー管理(GCAS BreakGlass)**がある。
  1. **事前に利用登録**が要る(申請者と、承認者のプロジェクトチームGCAS責任者の両方)。
  2. 本番リリースや移行など、**特定日の重要作業中にSSOが止まった緊急時にのみ**、申請する。
  3. 承認者に承認依頼メールが届く。承認されると、緊急アクセス用ユーザーが発行される。
  4. 緊急アクセス用ユーザーは、**申請から24時間で自動的に削除**される。

推論: 「事前登録」と「24時間で自動削除」は、普段は使えない緊急用の入口を、普段は閉じておく設計に見える。

## 6. GCAS Connect(旧 GMCN)

- ガイド: GCASのサービス群のひとつで、デジタル庁が提供する**ネットワークサービス**。2つの機能がある。
  1. 異なるCSP間の**プライベート接続**(P2P接続)
  2. デジタル庁などが提供する**共通サービス**(SaaSなど)へのプライベート接続(共通サービス接続)
- ガイド: 接続には、各CSPの閉域接続サービス(AWSなら**AWS Direct Connect**)を使う。CSPとの物理接続はGCAS Connect側が用意済みなので、利用者は**GCAS Connectの申込みと、CSP側の閉域接続サービスの設定**だけで開通できる。

| 項目 | ガイドの説明 |
|---|---|
| AWSの条件 | 本サービスで指定する Direct Connect パートナーで、**Hosted Connection型**の Transit VIF または Private VIF |
| 責任分解 | GCAS Connectは、**各CSP接続点までの回線と機器**が責任範囲。利用者は、物理的な設備の敷設が不要 |
| サービスレベル | 24時間365日、可用性の目標は**月間99.9%**。目標を外れても**補償はしない**。障害の問い合わせは24時間365日 |
| 納期 | 申請の受領後、**最大約10開庁日** |
| 料金 | GCAS Connectの責任範囲では**無料**。CSPの閉域接続サービスの料金は、利用者にガバメントクラウド利用料として請求(令和7年度現在) |

FAQ(ガイドの回答):
- 異なるCSP間の通信に、GCAS Connectの利用を**強制するものではない**。別の手段があるなら、GCAS Connectのほうが有利かを評価して判断する。
- CSP同士の連携が不要なら、必要になるまでGCAS Connectは**不要**。
- 共通サービスへの接続は、**共通サービスが受け付ける接続方式による**。GCAS Connect以外も受け付けるなら最適な方式を選べるが、GCAS Connectのみなら、単一CSPでも必要。

推論: この読みは [ネットワーク接続の補章](network-and-integration-aws.md) の内容と合う。マルチクラウドの原則([原則6](../principles/06-no-multicloud/README.md))があるので、GCAS Connectは「いつも要るもの」ではなく、必要が出てから検討するもの、と読める。

## 7. GCAS DevStack

- ガイド: デジタル庁が、ガバメントクラウド利用者向けに提供する、**Gitホスティングサービスと関連サービス**のプロダクト。現時点のGitホスティングは**GitLab**。ソースコード管理とCI/CD機能を含む。
- ガイド: 狙いは、Git、IaC、CI/CDの開発・運用手法を、**初期整備や学習コストが高くて始められない**状況をなくし、比較的簡単に始められるようにすること。

自分でGitホスティングを契約する場合と比べた、ガイドが挙げるメリット:

| メリット | 例(ガイド) |
|---|---|
| ガバメントクラウドとして推奨する**統制がかかった状態**で開発を始められる | クレデンシャル情報をソースコード・リポジトリに永続的に保持させない。ソースコードを誤ってインターネットに公開できない設定。脆弱性や問題のあるコードを早期に見つける静的解析。OSSの依存関係を把握する**SBOM(ソフトウェア部品表)**の生成 |
| **GCASアカウントでSSO**できる | 別にアカウントを発行・管理しなくてよい |

| 項目 | ガイドの説明 |
|---|---|
| 利用対象 | ガバメントクラウド利用者で、**ガバメントクラウド上のシステム**の開発・運用をする人。GCASアカウントを取得済みで、**デジタル庁との契約に紐づくライセンス**を契約済みの人。ガバメントクラウドと関係のない開発は対象外 |
| 提供範囲 | デジタル庁=Gitホスティング本体と関連機能、メンバー・ライセンス管理、SSO。**利用者=利用するCSP環境(開発環境も)と、コード管理・CI/CD等の設定** |
| 料金 | 利用者=ライセンス費用(**年額20万円程度/1ライセンス**、日割り)。デジタル庁=本体と関連インフラの費用 |
| 利用の流れ | ① PJMO管理者が見積もり〜契約 → ② ヘルプデスク経由で購入を申告(**DevStack追加特約への合意**が要る) → ③ GCAS DevStackでライセンスをアカウントに割り当て → ④ GCASアカウントで利用開始 |
| 期間の目安 | 見積もりから使えるまで**最低1か月程度**。**毎年10月頃〜翌年1月頃は、新規ライセンスの購入ができない**(デジタル庁側の調達の都合) |

制限事項(ガイド):
- ガバメントクラウド上の開発運用の目的でのみ使える。指定の方法で買ったライセンスのみ。
- インスタンス全体にかかわる設定は、利用者が変更できない。**GCASアカウントのSSOでのみアクセス**できる。
- **パブリックにアクセスできるリポジトリは作れない**。
- メンテナンスやバックアップで、使えない期間や**読み取り専用**になる期間がある。
- 利用するGitホスティング(GitLab)の**利用約款**(GitLab Subscription Agreement)も遵守する。

DevStack追加特約から(読んだ範囲):
- ライセンスは**最長1年**。更新は毎年度、定めの日までに申請する。
- 提供の終了は、**180日前までの通知**で可能(緊急の場合は事後通知)。
- 禁止事項の一つ: **Gitホスティングに、整備・運用する公共情報システムの利用者の個人情報に当たり得る情報を入力・保存すること**。ほかに、不正アクセス、過度な負荷、なりすまし、本来の目的以外での利用など。

推論: 本教材の [CI/CDとIaCの補章](cicd-iac-practice.md) で読んだ「統制のかかったパイプライン」を、実際に始める入口がDevStack、と読める。ただし、GitLabの使い方やパイプラインの書き方は、この公開ページには書かれていない(メンバー専用ページ「GCAS DevStack利用手続き」など)。

## 8. 「やったほうがいい / やめとけ」

| やったほうがいい(ガイド) | やめとけ(ガイド) |
|---|---|
| 利用が決まったら、まずGCASアカウントを取る | 個人で申請する(個人では申請できない) |
| 申請前に、ロール・承認者・準備物(マイナンバーカード、MFAデバイス)をそろえる | 開発運用委託業者が、守秘義務契約の前に申請する |
| 発行されたら、**2週間以内**にMFAを設定する | MFAを後回しにする(ロックされる) |
| セキュリティキーを、適切に管理する | セキュリティキーを第三者が入手できる状態にする |
| ソフトウェアMFAの人は、複数の認証方式を設定する | 認証方式を1つだけにして、パスワードを失くす |
| 異動・離任で不要になったら、速やかに削除する | 使わないアカウントを、放置する(90日以上で無効化されうる) |
| 本番相当環境(本番、共通運用管理、CI/CD)は、ハードウェアMFA | CI/CD環境を、本番相当ではないと考える |
| 接続元端末制限は、検証・開発環境にも効くと知っておく | 本番だけに効くと思い込む |
| 緊急アクセス(BreakGlass)は、**事前に利用登録**する | 緊急になってから、登録しようとする |
| GCAS Connectは、必要が出てから検討する。ほかの接続方式との比較で判断する | とりあえず全団体で作る |
| DevStackは、申込みに**最低1か月**を見込む | 10月〜1月に、新規購入しようとする |
| DevStackにはコードを置く | DevStackに、利用者の個人情報を入れる |

「やめとけ」の列も、上の各節でガイドが書いている内容(「できない」「禁止」「ロックされる」)を言い換えたもの。ガイドが「やめとけ」と明示した文は、DevStackの禁止事項(個人情報の保存)など一部。

## 9. ガイドが書いていないこと(読んだ範囲)

- GitLabの具体的な使い方、パイプラインの書き方、リポジトリの命名規則などは、公開ページにはない。
- GCAS BreakGlassの申請画面の操作、GCAS Connectの設計の詳細(アーキテクチャガイド、サービス仕様書)は、メンバー専用ページにある。
- ライセンスの年額(20万円程度)は「程度」で、正確な見積もりは、ガイドには書かれていない。
- 規程本文(権利義務、禁止事項、責任の範囲)は、読んでいない。使い始める人が必ず確認すべき内容が含まれている可能性が高いが、推論であって、ガイドから確認したことではない。
