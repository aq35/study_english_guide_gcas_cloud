# 4. 責任共有モデル — 段階3: なぜそう考えるのか

出典: 段階2の[原文の読み解き](../02-original/README.md)と同じ。
カタカナの `/` は息継ぎ。ルールは [linking-rules.md](../../../linking-rules.md)。
「ガイド:」はGCASガイドに書かれていること、「推論:」は筆者の推論。

## 一言で

マネージドサービスはCSPが担う範囲が広いので、自分たちの責任とリスクが小さくなる。

## ガイドが書いている理由

- ガイド: 「利用組織の責任範囲はマネージドサービスを利用することで狭めることができ、セキュリティリスクを軽減することができる」。
- ガイド: ただし、サービスの「設定内容は利用者側の責任」のまま。
- ガイド: 公共分野では、「実際の責任の有無に関わらず、説明責任を問われる場合があること」を想定しておく。

## ガイドが書いていないこと

- 説明責任を問われる場合の、具体的な事例。
- 責任範囲を3つに分けた理由。

## 推論

- 推論: 責任の外側にも説明責任が及ぶので、「責任範囲が狭い = 安心」とは言えない、と読める。文のつなぎ方は筆者による。

## 理由を英語で言ってみる

- **日本語訳**: マネージドサービスはリスクを減らすが、説明責任は問われうる。
- **English**: Managed services reduce risk, but you may still be held accountable.
- **カタカナ**: マニジドサーヴィスィズリデュースリスク / バッチュメイスティルビーヘルドアカウンタブル
