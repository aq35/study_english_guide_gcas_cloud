# 3. 単純移行で終わらせない — 段階3: なぜそう考えるのか

出典: 段階2の[原文の読み解き](../02-original/README.md)と同じ。
カタカナの `/` は息継ぎ。ルールは [linking-rules.md](../../../linking-rules.md)。
「ガイド:」はGCASガイドに書かれていること、「推論:」は筆者の推論。

## 一言で

モダン化すると、コストが下がり、開発が速くなり、セキュリティ品質が上がるから。

## ガイドが書いている理由

- ガイド: モダンアプリケーション化で、「クラウドサービス利用料削減や開発スピード向上、セキュリティ品質向上が可能」(4.2)。
- ガイド: バッチ処理のモダン化: コスト削減、サービス提供価値の向上、作業工数の削減。
- ガイド: マイクロサービスの利点: 高い変更容易性、開発サイクルの改善、高い耐障害性、柔軟なスケール。
- ガイド: システム間連携: 従来の方式は密結合で、「1つのシステムの障害や変更の影響が全体に及びやすい」ので、API連携を推奨。

## ガイドが書いていないこと

- 「単純移行」のままだと、どれくらい損をするかの数字。

## 推論

- 推論: 単純移行では、クラウドの標準的な効果(上の3つ)が出にくいから、モダン化を求めていると読める。ガイドは、単純移行の短所を直接は書いていない。

## 理由を英語で言ってみる

- **日本語訳**: モダン化すると、コストが下がり、開発が速くなり、セキュリティが良くなる。
- **English**: Modernizing lowers cost, speeds development and improves security.
- **カタカナ**: モダナイジングロウアーズコスト / スピーヅディヴェロプメント / アンインプルーヴズスィキュアリティ
