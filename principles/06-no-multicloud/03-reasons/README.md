# 6. マルチクラウドは原則禁止 — 段階3: なぜそう考えるのか

出典: 段階2の[原文の読み解き](../02-original/README.md)と同じ。
カタカナの `/` は息継ぎ。ルールは [linking-rules.md](../../../linking-rules.md)。
「ガイド:」はGCASガイドに書かれていること、「推論:」は筆者の推論。

## 一言で

コストが増え、運用が複雑になるから。

## ガイドが書いている理由

- ガイド: 理由は2つ: 「コスト増加」と「運用の複雑化」。
- ガイド: 禁止の対象は、「可用性や冗長性の確保を目的とした1つのシステム」での複数CSP利用。
- ガイド: 例外: 「真に必要な場合」。例は、データ分析やAIサービスで、主たるCSPでは要件を満たせない場合。

## ガイドが書いていないこと

- 「コスト増加」「運用の複雑化」の具体的な中身。
- 複数CSPを使わずに可用性や冗長性を確保する方法(この節には書かれていない)。

## 推論

- 推論: 複数のCSPにまたがると、認証、監視、コスト管理などの運用が、CSPの数だけ必要になる、と考えられる。ガイドは中身を挙げていない。

## 理由を英語で言ってみる

- **日本語訳**: マルチクラウドは、コストが増え、運用も複雑になる。
- **English**: Multi-cloud costs more and makes operations complex.
- **カタカナ**: マルティクラウドコスツモア / アンメイクスアペレイションズコンプレクス
