# 7. データの可搬性 — 段階3: なぜそう考えるのか

出典: 段階2の[原文の読み解き](../02-original/README.md)と同じ。
カタカナの `/` は息継ぎ。ルールは [linking-rules.md](../../../linking-rules.md)。
「ガイド:」はGCASガイドに書かれていること、「推論:」は筆者の推論。

## 一言で

CSPの変更には長い時間がかかり、データが移せないと乗り換えられないから。

## ガイドが書いている理由

- ガイド: 目的は、「経済合理性や事業戦略に応じた柔軟な対応を実現するため」。
- ガイド: 「CSPの変更は、数カ月から数年かけて行うことになることが想定される」。
- ガイド: 「アプリケーションやシステムだけを可搬にしても意味はない」ので、データの可搬性も含めて考える。

## ガイドが書いていないこと

- データの移行が、特に難しい理由。
- CSPの変更がどんな場合に起きるのか。

## 推論

- 推論: データが移せないと、アプリを移せても乗り換えは完了しない、というガイドの文3の言い換え。

## 理由を英語で言ってみる

- **日本語訳**: CSPの変更には何年もかかるので、データは可搬でなければならない。
- **English**: Changing CSPs takes years, so data must be portable.
- **カタカナ**: チェインジングシーエスピーズテイクスイヤーズ / ソウデイタマストビーポータブル
