# 2. ネイティブ利用 — 段階3: なぜそう考えるのか

出典: 段階2の[原文の読み解き](../02-original/README.md)と同じ。
カタカナの `/` は息継ぎ。ルールは [linking-rules.md](../../../linking-rules.md)。
「ガイド:」はGCASガイドに書かれていること、「推論:」は筆者の推論。

## 一言で

クラウドサービスのメリットを最大限に受けるため、独自機能を足さずにそのまま使う。

## ガイドが書いている理由

- ガイド: 「選定するCSPが提供するクラウドサービスのメリットを最大限享受できるよう」、独自の共通機能は作らない(原則)。
- ガイド: 例外は「必要最小限のガバナンスおよびセキュリティ設定」。
- ガイド: ネイティブに使えても、構築と運用の責任は利用システムにある。

## ガイドが書いていないこと

- 独自の共通機能を作ると、何が具体的に困るのかの説明。
- ゲート型の短所(ガイドは「従来のゲート型ではなく」と対比するだけ)。

## 推論

- 推論: 独自機能が増えるほど、クラウドの標準機能の更新や新機能の恩恵を、そのまま受けにくくなる、と考えられる。ガイドには書かれていない。

## 理由を英語で言ってみる

- **日本語訳**: フルのメリットを得るために、クラウドサービスをネイティブに使う。
- **English**: We use cloud services natively to get the full benefits.
- **カタカナ**: ウィユーズクラウドサーヴィスィズネイティヴリ / トゥゲットザフルベネフィッツ
